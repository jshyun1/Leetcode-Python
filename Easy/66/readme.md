# [Easy] 66. Plus One

> **문제 링크:** [LeetCode - Plus One](https://leetcode.com/problems/plus-one/)

## 📝 問題説明
大規模な整数を表す非空の整数配列`딜テグラム`が与えられます。 この整数は最も重要な桁が配列の先頭に来て、各要素は単一の桁を持ちます。 この整数に**1を加えた結果**を整数配列として返す問題です。 整数は前に不要な0を含みません。

* **例 1:** `digits = [1, 2, 3]` $\でしょうね$ 123 + 1 = 124 なので、`[1, 2, 4]` を返す。
* **例2:** `digits = [4, 3, 2, 1]` $\でしょうね$ 4321 + 1 = 4322 なので、`[4, 3, 2, 2]` を返す。
* **例3:** `digits = [9]` $\でしょうね$ 9 + 1 = 10 なので、`[1, 0]` を返す。

---

## 💡 アプローチ (Approach)

### 1. 直感的なアプローチ (Brute Force) - *失敗した、または非効率的な方法*
* **考えたロジック:** 配列を文字列でつなげた後、整数型（`int`）に変換し、そこに1を加えた後、再び文字列を経て桁数配列に分割する方法です。
* **限界点:** JavaやC++などの言語では、配列の長さが非常に長くなると、整数型データ型（int、long）の表現範囲を超える**オーバーフロー（Overflow）**が発生する可能性があります。 (Pythonは自動的に大きな数を処理しますが、アルゴリズムの趣旨には合いません。)

### 2. 最適化されたアプローチ (Optimized) - *最終通過した方法*
* **考えたロジック:** 数学で足し算をする時のように、**配列の最後（1の位）から前に来て1を足す方法**です。
* **解決手順:** 1. `range(len하며)) - 1, -1, -1)` を使って、後ろから桁数を一つずつ確認します。
  2. もし該当桁の数字が `9` より小さい場合は、単に `1` を足し、その位置で直接配列を返す（`return digits`）だけで完了します。 オリンス（Carry）が今後は届けられなくなるからです。
  3. もし該当桁が「9」であれば、1が加算されて「10」になるので、現在の桁を「0」にし、ループで先頭桁に繰り上げます。
  4. もし`[9, 9, 9]`のようにすべての数字が9でループが終わるまで返されなかった場合、結果は`[1, 0, 0, 0]`になるはずなので、最初に`[1]`を付けて返します。

---

## ⏱️ 複雑性 (Complexity)

* **時間計算量 (Time Complexity):** $O(N)$
  * 配列の最後から最大1回ずつしか巡回しないため、配列の長さ$N$に比例する時間がかかります。 (最良の場合、一の位が9でなければ$O(1)$で終わります。)
* **空間計算量（Space Complexity）：** $O(1)$ または $O(N)$
  * 基本的に既存の配列内で修正を行うため、追加のスペースは必要なく$O(1)$です。 ただし、すべての桁が`9`の場合にのみ桁が1つ増えた新しい配列が作成されるため、$O(N)$の空間が使用されます。
